Storage & Egress

기업 AI의 저장·전송 경계를 설계하는 방법

발행일: 2026-10-09 · 작성일: 2026-10-09

기업 AI에 자료를 연결할 때 먼저 정할 것은 모델 이름보다 데이터의 처리 범위입니다. 어떤 자료가 어디에 저장되고 외부로 전송되며 누가 그 결과를 사용할지 정해야 저장·전송·접근 조건을 업무에 연결할 수 있습니다.

  2. 02Separate storage and keys
  3. 03Inspect before sending
  4. 04Check local boundaries
  5. 05Tie controls to the workflow
01/

Map the data

첫 단계는 자료의 종류와 계정, 사용 목적을 연결하는 것입니다. 고객정보, 보험 자료와 사내 문서는 서로 다른 확인 조건을 가질 수 있습니다. 입력 원문, 모델에 전달할 내용, 결과물과 로그를 구분하고 각 단계의 보관 위치와 접근 주체를 확인합니다.

02/

Separate storage and keys

유니닷은 SQLCipher와 SecureStore를 사용해 저장 암호화와 키 보관의 경계를 분리합니다. 평문 대체 저장을 허용하지 않는 조건을 두고 키의 생성·사용·복구·삭제를 자료의 수명과 함께 검토합니다. 임시파일과 캐시도 검토 범위에 포함합니다.

03/

Inspect before sending

외부 연결에서는 전송 목적지와 자료의 허용 범위를 확인합니다. Presidio로 한국어와 산업별 식별자의 탐지·마스킹을 처리하고 업무 자료에 맞춘 평가 항목을 구성합니다. 마스킹 결과와 전송할 내용을 확인하는 단계는 저장 암호화와 별도로 둡니다.

04/

Check local boundaries

로컬 AI에도 API 접근과 외부 송신, 캐시·로그에 대한 확인 조건이 필요합니다. 유니닷은 llama.cpp를 사용하는 처리 흐름에 외부 송신 허용 목록과 API 접근 조건을 연결합니다. 자료가 로컬에 있다는 사실과 실행 중 허용되는 연결 범위를 각각 확인합니다.

05/

Tie controls to the workflow

처리 조건은 문서와 계정의 현재 상태, 동의와 업무 목적에 연결합니다. 판본 변경이나 삭제, 응답 유실 뒤 재시도와 같은 예외도 검증 항목에 포함합니다. 저장 경계와 전송 경계를 나눠 기록하면 조건이 바뀌었을 때 다시 확인할 위치가 분명해집니다.
