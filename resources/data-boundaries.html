기업 AI의 저장·전송 경계를 설계하는 방법

발행일: 2026-10-09 · 작성일: 2026-10-09

기업 AI에 데이터를 사용할 때는 저장할 내용과 외부로 보낼 내용을 먼저 정해야 합니다. 데이터의 종류와 보관 위치, 전송 목적지와 사용할 사람을 확인하면 처리 조건을 구체적으로 정할 수 있습니다.

01/

데이터와 사용 목적 확인

데이터의 종류와 계정, 사용 목적을 확인합니다. 고객정보·보험 문서·사내 문서의 조건은 다를 수 있습니다. 입력 원문, 모델에 전달할 내용, 결과물과 로그를 나눠 각 단계의 보관 위치와 접근 주체를 확인합니다.

02/

저장 암호화와 키 분리

저장 데이터를 암호화하고 키의 보관 경계를 분리합니다. 평문 대체 저장을 허용하지 않는 조건을 두고 키의 생성·사용·복구·삭제를 데이터의 수명과 함께 검토합니다. 임시파일과 캐시도 점검합니다.

03/

전송 전에 민감정보 확인

전송 목적지와 데이터의 허용 범위를 확인합니다. 한국어와 산업별 식별자를 탐지·마스킹하고 업무 문서에 맞는 평가 항목을 구성합니다. 마스킹 결과와 실제로 보낼 내용은 저장 암호화와 별도로 확인합니다.

04/

로컬 처리의 송신 조건 점검

로컬 AI에도 API 접근과 외부 송신, 캐시·로그에 대한 조건이 필요합니다. 외부 송신 허용 목록과 API 접근 조건을 적용하고 데이터가 로컬에 있다는 사실과 실행 중 허용할 네트워크 범위를 각각 확인합니다.

05/

변경·삭제·재시도 조건 기록

문서와 계정의 현재 상태, 동의와 업무 목적에 맞춰 처리 조건을 정합니다. 버전 변경·삭제와 응답 유실 뒤 재시도도 검증합니다. 저장과 전송 조건을 나눠 기록해 조건이 바뀔 때 다시 확인할 지점을 남깁니다.

06/
