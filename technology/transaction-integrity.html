Transaction Integrity

거래 무결성·중복 실행 억제

거래가 처리된 뒤 응답만 끊기면 다시 보내는 요청이 중복 처리를 만들 수 있습니다. 유니닷은 요청의 식별자와 처리 기록, 대상의 판본을 연결하고 이전 상태를 확인하는 복구 조건을 사용합니다.

Stable requests

재시도할 요청의 본문, 멱등키와 기한을 고정합니다. 같은 작업의 재요청과 새로운 작업을 구분하고 대상 ID와 현재 판본을 함께 검사합니다. 호출 전에 시도 기록을 저장해 이후 결과를 해당 요청에 연결합니다.

Result verification

처리 확인 응답의 대상 ID와 다음 판본을 확인합니다. 재고·견적 등 관련 상태가 응답과 일치하는지 살피고, 오래된 조회 결과가 최신 거래 상태를 덮지 않도록 반영 조건을 둡니다.

Uncertain outcomes

성공이나 실패를 확인할 수 없는 결과는 불명확한 상태로 보존합니다. 자동 재전송을 차단하고 이전 실행에 연결된 확인 자료로 결과를 정리합니다. 복구 중에도 기존 견적과 근거, 이전 실행 이력을 유지하는 조건을 적용합니다.

Failure scenarios

동시 요청, 처리 전후 중단과 응답 유실을 검증 항목으로 구성합니다. 중복 실행 억제와 데이터 보존, 복구 후 최신 상태의 반영을 함께 확인하고 각 검증 환경과 판본의 기록을 연결합니다.
